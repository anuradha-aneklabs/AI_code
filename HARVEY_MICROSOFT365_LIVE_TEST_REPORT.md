## 3. Codebase Architecture & Implementation Details

The Microsoft 365 integration is implemented in [harvey/integrations/microsoft.py](file:///C:/Users/aneka/Desktop/harvey/harvey/integrations/microsoft.py).

### Core Features Implemented:
1. **OAuth 2.0 Authorization Code Flow with PKCE:**
   - RFC 7636 Proof Key for Code Exchange (code verifier + SHA-256 code challenge).
   - Native loopback HTTP server on `http://localhost:8766` to intercept authorization response without client secrets.
   - Cross-Site Request Forgery (CSRF) protection via cryptographic `state` token parameter.
2. **Upgraded Scopes for Full Send & Read:**
   ```python
   READONLY_SCOPE = "offline_access https://graph.microsoft.com/Mail.Read https://graph.microsoft.com/Calendars.Read https://graph.microsoft.com/User.Read"
   SEND_SCOPE = "https://graph.microsoft.com/Mail.Send"
   FULL_SCOPES = f"{READONLY_SCOPE} {SEND_SCOPE}"
   ```
3. **Draft-Then-Send Architecture for RFC Message-ID Capture:**
   - In `send_email()`, creates a draft message via `POST /me/messages` (or `POST /me/messages/{thread_ref}/createReply` for threaded conversations).
   - Retrieves the immutable RFC `internetMessageId` generated by Exchange Online.
   - Dispatches via `POST /me/messages/{draft_id}/send`.
   - On dispatch failure, automatically deletes the draft message to prevent orphan draft accumulation.
4. **Sent Folder Verification (`verify_sent_message`):**
   - Added method to inspect dispatched message in Exchange Online via `GET /v1.0/me/messages/{message_id}`.
   - Validates subject, recipients, and timestamps.
5. **Safety Allowlist Enforcement:**
   - Detects live mode (`not is_mocked`) and strictly enforces `TEST_RECIPIENT_EMAIL` from `.env`.
   - Refuses dispatch to unapproved recipients with a safety block before any network request is issued.
6. **Token Refresh Rotation:**
   - Microsoft rotates refresh tokens on every exchange; [harvey/integrations/microsoft.py](file:///C:/Users/aneka/Desktop/harvey/harvey/integrations/microsoft.py) persists rotated refresh tokens atomically to `data/microsoft_token.json`.

## 5. Operator Activation Checklist (To Enable Live Sending)

To enable live Microsoft 365 sending, the operator must complete the following standard Azure Entra ID registration:

### Step 1: Register an App in Microsoft Entra ID
1. Navigate to [Microsoft Entra admin center](https://entra.microsoft.com/) (`entra.microsoft.com`).
2. Go to **Applications** $\rightarrow$ **App registrations** $\rightarrow$ **New registration**.
3. Fill in:
   - **Name:** `Harvey AI Sales Agent`
   - **Supported account types:** `Accounts in this organizational directory only` (Single tenant) or `Accounts in any organizational directory` (Multitenant).
   - **Redirect URI:** Select platform **Public client/native (mobile & desktop)** and enter:
     `http://localhost:8766`
4. Click **Register**.

### Step 2: Configure API Permissions
1. Under **Manage**, select **API permissions** $\rightarrow$ **Add a permission** $\rightarrow$ **Microsoft Graph** $\rightarrow$ **Delegated permissions**.
2. Add the following permissions:
   - `Mail.Read`
   - `Mail.Send`
   - `User.Read`
   - `Calendars.Read`
   - `offline_access`
3. Click **Add permissions**. (No admin consent required for delegated personal mailbox permissions).

### Step 3: Populate `.env`
Copy the identifiers from the App Overview into `.env`:
```env
M365_CLIENT_ID="<Application (client) ID from Azure Portal>"
M365_TENANT_ID="<Directory (tenant) ID or 'organizations'>"
TEST_RECIPIENT_EMAIL="approved.recipient@example.com"
```

### Step 4: Run OAuth Authorization
Execute the authorization command:
```powershell
.venv\Scripts\python.exe -m harvey.cli microsoft auth
```
A browser window will open requesting user consent for the mailbox. Upon approval, Harvey stores the encrypted refresh token at `data/microsoft_token.json`.

### Step 5: Verify Connection
Test connectivity without sending:
```powershell
.venv\Scripts\python.exe -m harvey.cli microsoft test
```
