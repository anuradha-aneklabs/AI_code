## 3. Microsoft 365 Architecture & Readiness

The Microsoft 365 integration in [harvey/integrations/microsoft.py](file:///C:/Users/aneka/Desktop/harvey/harvey/integrations/microsoft.py) mirrors all enterprise capabilities verified on Gmail:

1. **PKCE Security:** Implements RFC 7636 Proof Key for Code Exchange with SHA-256 challenges, eliminating the need for client secrets in desktop/daemon deployments.
2. **Draft-Then-Send Reliability:** Microsoft Graph allows drafting a message first (`POST /me/messages`), fetching the immutable internetMessageId generated by Exchange Online, and then dispatching (`POST /me/messages/{id}/send`). If dispatch fails, the draft is cleanly rolled back and deleted.
3. **Threading Architecture:** When replying to a prospect, Harvey invokes `POST /me/messages/{thread_ref}/createReply`. Exchange Online automatically sets the proper `In-Reply-To` and `References` headers, guaranteeing conversation thread continuity in Outlook and mobile clients.
4. **Token Rotation:** Microsoft Entra ID rotates refresh tokens on every token issuance. Harvey captures the new refresh token from the token endpoint response and atomically writes it to disk.

## 4. Multi-Layer Safety Architecture

Both email providers are shielded by Harvey's non-negotiable safety guardrails:

```
  ┌─────────────────────────────────────────────────────────────┐
  │                 Outreach Generation (AI)                    │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │              Outbox Staging (pending_review)                │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │      HUMAN REVIEW GATE (require_approval = True)            │
  │      - Operator must explicitly click "Approve"             │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │      SENDING SAFETY MODE (sending_paused Safety Hold)       │
  │      - Blocks automated dispatch during evaluation          │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │      TEST RECIPIENT ALLOWLIST GATING                        │
  │      - In live mode, recipient must match TEST_RECIPIENT_EMAIL │
  │      - Rejects any unauthorized destination address         │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │              Live Mail API Dispatch (Gmail / M365)          │
  │              - Dispatches exactly approved message          │
  │              - Confirms message ID and folder presence      │
  └─────────────────────────────────────────────────────────────┘
```

1. **Human Approval Gate:** Every message drafted by the AI engine enters the `outbox` table in `pending_review` status. It cannot be transmitted without manual human intervention.
2. **Global Sending Safety Hold:** The `sending_paused` setting (`Pilot Evaluation - Read-Only Safety Hold`) prevents background cron workers or bulk drainers from autonomous transmission.
3. **Allowlist Enforcement:** Even when approved, live dispatch is gated against `TEST_RECIPIENT_EMAIL` in `.env`. Attempting to send to any address outside this allowlist fails closed with a safety block.
4. **Duplicate-Send Protection:** The database enforces a `UNIQUE(campaign_id, prospect_id, step)` constraint on the `outbox` table, preventing duplicate emails to the same prospect.
5. **Preserved Invariant:** Total live emails sent across the entire database lifetime is strictly **1** (the authorized test email).
